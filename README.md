# Портфолио — Руслан Качев

Одностраничный сайт-портфолио: верстка, SEO-разработка и продвижение.
Чистый HTML, CSS и ванильный JS — без сборки, без фреймворков, без зависимостей.

## Что внутри

```

├── app.js                тема, ресайзер вьюпорта, окно «Написать мне», копирование контактов

    ├── law/              «Клюев и партнёры» — юрбюро
```

Разделы страницы: герой с живым ресайзером вьюпорта → услуги (9 блоков, включая SEO
и продвижение) → работы (5 кейсов с демо) → процесс → цены (3 пакета в столбец,
старая цена зачёркнута) → обо мне → FAQ → контакты.

## Локальный просмотр

Открывать через сервер, а не файлом — иначе демо-разделы могут вести себя иначе:

```bash
cd portfolio
python3 -m http.server 8000
# http://127.0.0.1:8000/
```

## Публикация на GitHub Pages

1. Создать репозиторий, например `portfolio` (публичный).
2. Загрузить содержимое этой папки в корень репозитория (файл `index.html` должен лежать в корне).
3. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, папка `/ (root)`.
4. Через минуту сайт будет на `https://<логин>.github.io/portfolio/`.

Важно: файл `.nojekyll` уже лежит в корне — без него GitHub Pages не отдаст папку
`works/kuhnya/_astro/` (Jekyll игнорирует каталоги, начинающиеся с подчёркивания),
и демо кухонь останется без стилей и картинок.

После публикации поменять в `index.html`:

- `og:url` и `canonical` — когда появится постоянный адрес (сейчас не заданы);
- ссылки на репозиторий в карточках работ — если код будет открыт.

`works/kuhnya/` — статическая сборка клиентского сайта, подготовленная для показа:
все ссылки сделаны относительными, чтобы работать из подпапки, форма заявки

GitHub Pages нет). Сам сайт с формой и бэкендом живёт на хостинге клиента.
