# Портфолио — Руслан Качев

Одностраничный сайт-портфолио: верстка, SEO-разработка и продвижение.
Чистый HTML, CSS и ванильный JS — без сборки, без фреймворков, без зависимостей.

## Что внутри

```
portfolio/
├── index.html            разметка всего сайта
├── styles.css            стили, темы (светлая/тёмная)
├── app.js                тема, ресайзер вьюпорта, окно «Написать мне», копирование контактов
├── 404.html              страница ошибки для GitHub Pages
├── favicon / robots.txt
├── assets/works/         превью работ (jpg)
└── works/                живые демо-стенды
    ├── kuhnya/           «Ваша Кухня» — 18 страниц, Astro, SEO (статическая копия)
    ├── coffee/           «Обжарка» — лендинг кофейни
    ├── law/              «Клюев и партнёры» — юрбюро
    ├── fitness/          «Высота» — фитнес-клуб
    └── email/            рассылка «Обжарка» — email-верстка
```

Разделы страницы: герой с живым ресайзером вьюпорта → услуги (9 блоков, включая SEO
и продвижение) → работы (5 кейсов с демо) → процесс → цены (3 пакета в столбец,
старая цена зачёркнута) → обо мне → FAQ → контакты.

## Локальный просмотр

Можно просто открыть `index.html` двойным кликом: демо-стенды работают и по `file://`,
все ссылки внутри них ведут на конкретные `index.html`, а не на папки
(иначе браузер показал бы список файлов вместо сайта).

Если нужен сервер — как на хостинге:

```bash
cd portfolio
python3 -m http.server 8000
# http://127.0.0.1:8000/
```

## Публикация на GitHub Pages

Сайт уже опубликован:

- **Демо:** https://ruslangit1235.github.io/portfolio/
- **Репозиторий:** https://github.com/Ruslangit1235/portfolio
- Ветка `main`, папка `/ (root)`, обновление — обычный `git push`.

Важно: файл `.nojekyll` лежит в корне — без него Pages не отдаст папку
`works/kuhnya/_astro/` (Jekyll игнорирует каталоги, начинающиеся с подчёркивания),
и демо кухонь останется без стилей и картинок.

Обновление сайта после правок:

```bash
cd portfolio
git add -A && git commit -m "что поменялось" && git push
```

Pages пересобирается минуту-две. Первый деплой после `git push` иногда нужно
проверить в Actions → pages build and deployment.
